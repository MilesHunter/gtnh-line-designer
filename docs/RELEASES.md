## 0.3.0 — 机器族、自动排版与导出修复（2026-11-25）

### 发布信息

| 项目 | 内容 |
| --- | --- |
| `package.json` 版本 | `0.3.0`，与 tag 一致 |
| Tag / Commit | `v0.3.0` / 发布后回填 |
| Release 正文 | [docs/RELEASE_NOTES_v0.3.0.md](RELEASE_NOTES_v0.3.0.md) |
| 便携包 | `GTNH-Line-Designer-0.3.0-portable-x64.zip` |
| ZIP SHA-256 | 发布后回填 |
| 校验文件 | `SHA256SUMS.txt` |

### 确认功能

**机器选择**

- 单方块机器按机器族合并基础、进阶、精英等电压变体；搜索“离心机”只显示一个单方块入口，具体等级由节点电压配置。
- 机器选择统一区分单方块、多方块和巨型多方块，并保留工业离心机、巨型化学反应釜等独立机器。
- 从配方搜索选定具体机器后立即收起机器列表，节点保存该机器与配方。
- 检查器将已选机器显示为只读摘要；仅在主动点击“更换机器”时显示机器下拉框。

**画布与排版**

- 新增“自动排版”：按物料流方向对机器节点分层，减少节点重叠和连线交叉。
- 自动排版按节点宽度和端口高度计算间距，并把整次移动合并为一步撤销。
- 节点连线改为带圆角的折线路径，长距离产线和扇入扇出更容易追踪。

**PNG 导出**

- 修复导出 PNG 卡死：不再用 DOM 克隆内联 24 MB 图集，改为 Electron 原生截屏导出当前视图。
- 导出时隐藏 MiniMap、缩放控件和空状态提示，并显示导出状态与错误。
- 当前导出为当前视图、窗口原生分辨率；整图和高分辨率导出列入 [ROADMAP.md](ROADMAP.md)。

**兼容与发布边界**

- 0.1.0 / 0.2.0 的 `.gtnhgraph` 项目继续可用，旧格式打开时自动迁移。
- Release 不包含任何 GTNH 配方数据；首次使用需在线下载 data v7，或从本机实例执行 NESQL 导入。
- 仍是 Windows x64 便携包，数据、项目、设置和日志保存在程序目录。

### 核对结论

- 待 Release workflow 完成后，补充 Commit、ZIP SHA-256 与发布状态。

## 0.2.0 — 机器节点重构（2026-10-26）

### 发布信息

| 项目 | 内容 |
| --- | --- |
| `package.json` 版本 | `0.2.0`，与 tag 一致 |
| Tag / Commit | `v0.2.0` / `4523f86` |
| Release 正文 | [docs/RELEASE_NOTES_v0.2.0.md](RELEASE_NOTES_v0.2.0.md) |
| 便携包 | `GTNH-Line-Designer-0.2.0-portable-x64.zip`（229 MB） |
| ZIP SHA-256 | `6717a819801943827204248d14812954f7e06104928f0aca065858ab6975b53e` |
| 校验文件 | `SHA256SUMS.txt` 已随 Release 上传 |

### 确认功能

**机器节点重构**

- 配方节点升级为具体机器节点，一台机器节点只安排一个配方，并区分单方块与多方块。
- 可以先放置空机器节点，再在右侧检查器中选择该机器支持的配方。
- 同一条配方可由多台机器执行时，明确列出具体机器，由玩家选择后才能创建节点。
- 节点采用左输入、右产物两列布局，默认折叠多余端口，可在节点内展开。
- 机器名称中文优先，已知机器支持中英文搜索；缺少译名时安全显示原名。
- 右侧配方搜索绑定当前机器，直接点击配方即可配置，不再重复选择机器。
- 项目格式升级到 schema v2，旧 v1 项目打开时自动迁移；缺失配方和机器保留并标记。

**搜索与数据兼容**

- 左侧拆分“机器搜索”和“原料 / 产物搜索”。
- 原料/产物通过具体物品、流体或矿辞芯片精确匹配；两边同时填写时取交集。
- 配方结果按机器类别折叠分组，不显示时间与能耗摘要，优先突出原料、产物和可用机器。
- 单方块/多方块识别同时支持英文与中文 NESQL tooltip，已导出的 2.8.4 和 2.9.0 本地数据无需重新导出。
- 升级便携目录时可以直接复制整个 `data` 目录，继续使用已有缓存。

**计算流程**

- 节点实时显示理论输入、输出、功率、建议机器数和负载率；整线计算仍由“计算”按钮触发。
- 电压低于配方基础等级时节点无效；超频只由超过基础电压触发。
- 线圈只对支持线圈的多方块机器开放，并行按具体机器规则计算。
- 计算前校验整图，无效节点高亮并阻止求解。
- 计算使用可取消的阶段进度弹窗，完成后自动关闭。
- 修改配置后保留上一次结果并标记“已过期”，不会自动重新计算。

**性能与稳定性**

- 以 500 节点、1,000 条边作为交互验收规模。
- 画布只渲染可见节点，拖动时只替换被移动的节点对象。
- 单节点预览按变化节点批量发送到 Worker。
- 撤销历史改为节点和边的增量记录，不再为每一步复制整张项目。
- 修复中文本地数据机器类型全部显示为多方块的问题。
- 不兼容物料在连线阶段直接拒绝，悬空连线在计算前静默清理。

**发布边界**

- Release 不包含 `data.bin.gz`、`atlas.webp` 或任何 GTNH 配方数据包。
- 数据可在线下载，或通过本机 NESQL 导出后导入。
- 本机导出数据只适用于对应的整合包版本、模组集合和配置。
- 依旧是 Windows x64 便携包，核心数据、设置、项目与日志保存在程序目录，不写入 `%APPDATA%`。

- ZIP 与 `SHA256SUMS.txt` 均已上传；ZIP 校验值取 Release 资产页显示的 SHA-256。

| Release 正文 | [docs/RELEASE_NOTES_v0.1.0.md](RELEASE_NOTES_v0.1.0.md) |
| 便携包 | `GTNH-Line-Designer-0.1.0-portable-x64.zip`（229 MB） |
| ZIP SHA-256 | `E99DC08BDCA6E6E0D406289507487C4D19300A00F1C7E1AC95AE3AEEA16F9DDD` |
| 校验文件 | 无独立 `SHA256SUMS.txt`，SHA-256 写在 Release 正文中 |

### 确认功能

**编辑器**

- 节点式配方画布、端口连线和节点检查器。
- 按产物搜索和按原料搜索，保留全部配方变体。
- 机器数量模式、目标输出、电压、线圈、超频和并行配置。
- 撤销重做、复制粘贴、框选、缩放、MiniMap 和 PNG 导出。
- `.gtnhgraph` 项目保存、打开、自动保存和崩溃恢复。

**计算**

- 用户点击“计算”后求解，不随编辑操作自动计算。
- 支持物品、流体、矿辞、概率产物、容器转换和机器专属参数。
- 支持扇入扇出、边优先级、外部端口和回收环。
- 汇总外部原料、外部盈余、各电压等级功率和循环警告。

**数据**

- GTNH data v7 在线数据下载。
- 下载支持超时、重试、Range 续传、镜像回退和错误提示。
- 本机 GTNH 实例 NESQL 导入。
- GTNH 2.9.x 使用 NESQL `0.5.7-ShadowTheAge`；GTNH 2.8.4 使用独立 NESQL `0.5.6-ShadowTheAge`。
- 导出环境支持 BugTorch 和已有 NESQL JAR 的事务性恢复。
- 数据缓存、项目、设置和日志保存在程序目录，配方数据不写入 `%APPDATA%`。

**发布边界**

- 不包含 GTNH 配方数据包。
- 不自动启动游戏。
- 不自动展开完整上游依赖树。
- 不实现完整电网和自动发电平衡。

### 已知限制

- 本机导入不会自动启动游戏。
- NESQL 配方范围受上游 exporter plugin 限制。
- 用户添加额外模组后需要重新导入数据。
- 2.9.0-beta-3 已端到端验证；2.8.4 使用独立构建并通过真实实例导出验收。

### 核对结论

- tag 与 `package.json` 版本一致。
- Release 正文与仓库内 `docs/RELEASE_NOTES_v0.1.0.md` 一致。
- 该版本早于自动发布 workflow，资产只有便携 ZIP，没有 `SHA256SUMS.txt`。
- 已发布 ZIP 的 SHA-256 与本地 `release/` 中同名构建产物不同（本地为 `24BC85EB…`，发布页为 `E99DC08B…`），说明两者不是同一份文件；用户校验以 Release 页面和正文为准。

## 未发布变更

0.3.0 发布后暂无新的未发布功能改动。后续改动继续先记入 `CHANGELOG.md` 的 Unreleased，再在发版时迁入对应版本。

## 发布核对清单

每次发布时按顺序执行，并在完成后更新本文件：

1. 更新 `package.json` 的 `version`，确认没有意外的未提交改动。
2. 新建 `docs/RELEASE_NOTES_v<version>.md`，内容面向玩家，只写本版本真实包含的功能。
3. 把 `CHANGELOG.md` 的 Unreleased 条目归入新版本，并更新本文件的版本总览。
4. 本地执行 `npm ci`、`npm run typecheck`、`npm test`、`npm run package`。
5. 提交代码，打与 `package.json` 一致的 annotated tag，推送 `main` 和 tag。
6. 等待 Release workflow 完成，确认 Release 正文、ZIP 与 `SHA256SUMS.txt` 都已生成。
7. 把 Release 页面上的 ZIP SHA-256 填回本文件对应版本，并把状态从“开发中”改为“已发布”。
8. 如果 Release 被重新构建，更新本文件中的校验值，并注明覆盖时间。
